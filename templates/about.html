About GradePath

How the app turns student information into GPA estimates, where analysis data is kept, and what the current architecture is good at.

PROJECT OVERVIEW

A lightweight prediction and analysis app

GradePath is a Python Flask application. It accepts nine study, attendance, and support-related features, then uses a bundled, pre-trained Random Forest model to estimate GPA and a letter grade. The model runs inference only; it is not trained or updated by this app.

Architecture and data flow

The same Flask backend serves the pages and prediction APIs.

  1. 01

    Browser interface

    Jinja-rendered HTML, CSS, and JavaScript provide the prediction form, dataset upload, and dashboard. Plotly.js renders charts in the browser.

  2. 02

    Flask application

    Routes validate single-student inputs and accept CSV or XLSX uploads up to 5 MB. Uploaded files are processed in memory, not saved as source files.

  3. 03

    Data cleaning

    Batch uploads are checked against the required feature schema. Invalid or missing values are filled, duplicate feature rows are removed, and a cleaning summary is produced.

  4. 04

    Pre-trained model

    The bundled scikit-learn Random Forest estimates GPA. Grade bands convert that value to a letter grade; the dashboard displays the results and summary charts.

  5. 05

    Analysis storage

    Locally, analysis records are stored in SQLite. On Vercel, SQLite is temporary and instance-local, so a bounded copy is also kept in the browser's signed session cookie to make recent results available across requests.

WHAT WORKS WELL

Pros

  • One Python app handles validation, cleaning, prediction, and dashboard data.
  • The pre-trained model is loaded for inference; app users do not need a model-training pipeline.
  • Uploaded source files are processed in memory instead of being kept as files.
  • The browser session helps preserve the latest analysis when Vercel routes requests to different instances.

CURRENT TRADE-OFFS

Cons and limitations

  • Vercel's SQLite copy is temporary and not shared, so it is not a durable history store.
  • The session cookie is signed, not encrypted. Its analysis values—including predictions and any supplied actual GPA or grade—are readable to anyone with access to that browser's cookies.
  • Browser storage is size-limited; large analyses may be reduced to fit. Session history is not shared across browsers or devices.
  • Predictions are estimates from the existing training data, not guarantees or a substitute for educator judgment.
  • The current app has no user accounts or access-control layer for shared deployments.
Before using real student records: move session payloads to encrypted, access-controlled storage, use a durable shared database, and configure production secrets and access controls.
